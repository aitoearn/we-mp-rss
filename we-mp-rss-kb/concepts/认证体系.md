# 认证体系

## 概述

WeRSS 支持三层认证机制，按优先级依次匹配：级联 AK/SK → 用户 AK/SK → JWT Token。

## 认证方式

| 方式 | 用途 | 实现 |
|------|------|------|
| JWT Token | Web UI 登录会话 | `core/auth.py`、`apis/auth.py` |
| Access Key (AK-SK) | API 程序化调用 | `core/models/access_key.py`、`web.py` AKMiddleware |
| 级联 AK/SK | 父子节点通信 | `core/auth.py` 级联节点认证 |

## JWT 流程

1. 用户登录 → `POST /api/auth/login`
2. 返回 access_token
3. 后续请求带 `Authorization: Bearer {token}`

## AK-SK 流程

1. Admin 在 Web UI 创建 Access Key
2. 请求头：`Authorization: AK-SK {ak}:{sk}`
3. `AKMiddleware` 解析并注入 `request.state.ak_auth`

## 权限模型

- **admin**：全部权限
- **普通用户**：按 `permissions` 字段细粒度控制
- 前端路由守卫见 [[web_ui模块]]

## 注意事项

- 生产环境必须修改默认 `secret`（环境变量 `SECRET_KEY`）
- 不要提交 `config.yaml` 中的真实密钥
- RSS 订阅端点无需认证（公开）
